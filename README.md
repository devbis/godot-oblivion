# OpenOB

OpenOB is an early Godot prototype that reads Oblivion's installed `Data` directory at runtime. It does not include game data. The current milestone indexes the base game's ESM4 cells and BSA archives, converts NIF meshes and diffuse textures, and assembles the player and placed NPCs on the original 71-bone skeleton. It reads original idle, directional walk, fast-movement, and jump KF sequences and plays them in Godot. It applies NPC FaceGen head shapes, expression morphs, and blinking. Static collision is generated from render triangles as a temporary approximation; original Havok collision is not implemented.

## Requirements

- Godot 4.7.2 stable, using the built-in Jolt 3D physics backend. The Godot engine is installed separately and is not included in this repository.
- CMake 3.22+, a C++20 compiler, and zlib.
- The matching `godot-cpp` 4.7 API source tree at `extern/godot-cpp` and the `nifly` NIF parser source at `extern/nifly`. These third-party sources are not included in this repository.
- The base Oblivion game installed locally, including `Oblivion.esm` and its BSA files.

## Build

Build and run the standalone data inspector:

```sh
cmake -S native -B build
cmake --build build
ctest --test-dir build --output-on-failure
./build/oblivion-inspect "/path/to/Oblivion/Data" ImperialDungeon01
```

The GDExtension build uses the 4.7 API in `extern/godot-cpp` plus `nifly` to parse NIF geometry, skin weights, skeleton nodes, and KF transform tracks. These third-party dependencies are supplied locally and are excluded from this repository.

```sh
godot --headless --editor --path . --quit
```

Run the project and provide the game's `Data` directory either as an environment variable or a user argument:

```sh
OBLIVION_DATA_DIR="/path/to/Oblivion/Data" godot --path .
godot --path . -- --game-data "/path/to/Oblivion/Data"
```

Quests need the game executable to read its script command table. Set `OBLIVION_EXE` to `Oblivion.exe`; without it the project looks for `Oblivion.exe` next to the `Data` directory's parent (`<install>/game_info/data/Oblivion.exe` for a `<install>/game_info/data/Data` directory). Pass `--start-at-sewer-exit` after `--` to begin at the Imperial Sewer exit instead of in the prison cell. Controls: `WASD` move, `Shift` run, `E` jump, `Space` interact, `Ctrl` crouch (slower, lower capsule and camera; no crouch animation yet), `R` first/third person, `F` draw or sheathe the weapon, `X` next weapon (bare hands after the last), `N` face profile, `U` face view, `Y` fly (`E` rises, `Ctrl` descends). `M` opens a scrollable list of every original idle/gesture KF found under `Meshes/Characters/_male/idleanims` (pointing, arms crossed, saluting, cheering, praying, pondering, talk gestures and more); click an entry or press `Enter` to play it on the player, and `,` / `.` step to the previous/next clip without the list. Clips are enumerated from the archives at runtime and loaded on first use; the first sequence in the file plays, looping if its cycle type is loop and otherwise once. Moving, jumping or crouching cancels the gesture. Disabled while loading, in the inventory, or in face view. Press `F9` to start the `CharacterGen` quest by hand; it also starts once the first NPCs of a cell exist.

The in-game reader searches for `Oblivion.esm` and all `.bsa` files in that directory. Loose files override archived resources. The GDScript controller uses editable placeholder movement values; those values are not presented as verified Oblivion physics.

## Current support

- Oblivion BSA version 103 directory parsing and zlib asset extraction.
- Base-game ESM4 CELL, placed-reference, door-target, NPC AI-package, item world/equipment model-path, and float GMST indexing. ARMO/CLOT world models come from `MOD2`/`MOD4`; wearable models use `MODL`/`MOD3`.
- Imperial Prison discovery through editor ID `ImperialDungeon01`.
- Asynchronous ESM/BSA indexing and NIF parsing through `OblivionData`, plus case-insensitive loose/BSA asset lookup.
- Static NIF mesh extraction with node transforms, triangle/UV/normal arrays, diffuse texture paths, and per-shape alpha blend/test flags; parsing runs on a worker thread and Godot resource creation runs on the main thread.
- Diffuse DDS, TGA, PNG, and JPEG loading from loose files or BSA archives. DDS files with incomplete mip chains are decoded from their top mip and receive a regenerated mip chain.
- The Imperial male body is assembled from original upper body, lower body, hand, and foot meshes, with the original human head and hair. Skin weights bind those meshes to `Characters/_male/skeleton.nif`.
- The default male avatar is currently dressed with the base game's `LowerShirt05` and `LowerPants05` CLOT models, looked up by ESM editor ID and skinned to the same skeleton. This outfit choice is a prototype default; its match to the original player's starting inventory has not been verified. Female model paths are available from the same records.
- Original idle, forward/backward/left/right walking, four fast-movement directions, and jump start/loop/land KF sequences are loaded at runtime. The prototype samples translations linearly and rotations with quaternion slerp; WASD selects direction, Shift selects the fast sequence, and airborne/floor transitions select the jump sequences. NPC route actors also switch between forward and fast-forward clips based on their route speed.
- The centered third-person camera stays directly behind the player's facing direction. Captured horizontal mouse motion immediately turns the player; vertical motion adjusts pitch. Mouse wheel and trackpad pan gestures adjust camera distance, and the trackpad magnify gesture also zooms. A sphere sweep checks the full camera path against streamed cell collision, shortening the camera distance before it reaches a wall and easing back to the selected distance once clear. Zoom changes move the camera directly, without waiting for a physics tick. Press `R` to switch between the third-person camera and a first-person view from the head (the reticle stays; the whole third-person body is hidden, so looking down shows nothing). Press `U` or click the face-view button to move the camera in front of the player for expression checks; the close-up tracks the animated head and allows very close inspection. Toggle again to restore the prior camera distance and pitch. The pointer is captured after the cell loads, captured again when the app regains focus, and released with Escape. Distance, sensitivity, and pitch remain prototype values because the original camera measurements are not established.
- `scripts/interaction_targeting.gd` follows a ray from the camera through the screen centre and returns one target snapshot (kind, action, reticle icon, crime, locked, lock level); `scripts/hud_controller.gd` draws it and `Space` acts on that same snapshot, re-checked when the key is pressed. The HUD shows a centered reticle with the original activation icon (item, container, door, NPC), target name/lock level, the original health, magicka, and fatigue ribbons with numeric current/max values, a heading compass, and the active weapon/selected spell icons and names. Initial actor values come from the installed `Player` NPC record; magicka uses Oblivion's 2×Intelligence rule when the record has no base value. New sessions start at those maxima. Combat, spell costs, regeneration, race/birthsign modifiers, and save persistence are not implemented, so runtime values stay at their starting values until gameplay systems update them. The reticle turns red `(208, 0, 0)` for a crime target or a locked door; the locked-door tint is a design choice, not a verified original behavior. Icon indices, ranges, ribbon visibility, and compass layout are provisional. The compass follows heading but has no quest/location markers yet. The HUD is hidden while loading, in the inventory, and in face preview. NPCs show the talk icon, and `Space` shows "Dialogue unavailable"; containers are targetable but have no contents yet. Reach is measured from the player's body, not from the camera: 1.8 m for items, 2.5 m for doors, and 1.5 m for NPCs (the original `iActivatePickLength`, 150 units), so zooming the third-person camera out does not change it. Press `Space` while aiming at a placed world item to pick it up; a picked-up item stays gone when its cell is loaded again. The HUD counts inventory items, including duplicate copies. Press `I` to inspect inventory quantities and equipped gear; click an ARMO, CLOT, or WEAP entry to equip it again. Click a known spell there or press `Q` to change the selected spell. ARMO/CLOT items use their biped-slot masks and replace overlapping gear; WEAP items attach to the right hand. Other supported item types go into the prototype inventory only. Aiming at a linked door and pressing `Space` follows it; a locked door shows "Locked" and never transitions, and an unlinked door opens or closes with its original NIF animation.
- A linked-door transition unloads the current cell's NPC nodes, loads the target cell's geometry and placed NPCs, and applies the door's destination position and heading. Player inventory and avatar remain across the transition.
- Placed `ACHR` NPC references use their ESM transform, race sex flag, hair record and color, original hair/clothing/armor/weapon NIFs, and the original rig. The ESM `BMDT` biped-slot mask prevents carried armor and clothing from overlapping: `DOFT` outfit pieces take precedence, and actors without a default outfit select non-overlapping inventory armor before clothing. One inventory weapon is attached to the right hand; the active weapon slot is not parsed yet, so this uses the first WEAP entry. NPC routes come from the packages the quest driver selects for each NPC at the current quest stage (`select_package`) and from a navigation mesh baked in tiles from the cell's collision, not from hand-placed marker lists; humanoid NPCs open doors on their path, while creature actors do not. Killed or disabled NPCs stay removed. Route speeds use each package's `Always run` flag when available. The package selection is still an approximation of the original package-condition evaluator. Actors use approximate `CharacterBody3D` capsules, snap to generated walkable geometry when a floor is found, and use gravity and floor snapping there; in cells with no generated floor, their ESM route height is retained.
- NPC base parsing retains each record's `FGGS`/`FGGA` FaceGen coefficients and race. Human NPCs use the Imperial human head template; Argonians, Khajiit, and Orcs select their own head NIF plus matching EGM/TRI data. The current Imperial Prison cell exercises individual human coefficients; the nonhuman paths are available for cells that contain those races. The player's original hair keeps its NIF alpha cutout and follows the head bone. Original eyes, mouth, teeth, and tongue meshes are placed in the skeleton's head space. Each head's expression and static morphs are loaded with its own TRI data, and NPCs and player blink on independent timers. Press `G` to cycle the nearest NPC through expressions, or `H` to cycle the player's expression; both blend smoothly and skip expressions absent from that head mesh. The player can cycle through the default human face and distinct human NPC FaceGen profiles with `N`; each selection rebuilds the original head from that NPC's stored coefficients. This is a profile preview, not the original character creation slider system.
- Generated mesh, texture, and static concave-collider resources are cached using source hashes and the converter version, under the ignored `.godot/openob/cache` directory when run from the editor and under `user://openob/cache` in an exported build. Files of older converter versions are removed, and the oldest files go when the cache passes 2 GiB.
- Static `ConcavePolygonShape3D` colliders are built from the render geometry for placed NIFs, with collision enabled from either triangle side; sky, dust, and light-beam shapes are excluded. They do not reproduce original Havok collision data. The player starts at the placed `CGPlayerStartMarker` (`0x00032AB5`); the first valid NPC reference is only a fallback if that marker is absent. At startup and after a linked door transition, the controller raycasts for a walkable generated surface and places the player on it. Avatar meshes are offset by the rig root's rest height so the visible soles align with the capsule base. An invisible 6×6 m support is created only when no walkable surface is found below the destination. Placed NIFs that carry Havok bodies become rigid bodies joined by their ragdoll and limited-hinge constraints (chains, the rope and bucket of `CGRopeBucket01`); a rope that is a skinned mesh follows the bodies of its bones through a skeleton. Every such body with mass can be carried with the grab key (`grab_enabled`); doors, static anchors and animated references cannot, and there is no weight limit.
- Fixture coverage for ESM4 links/transforms and BSA extraction.
- Idle manager (script-triggered). The 650 `IDLE` records of the master are indexed as a tree: `MODL` is the `.kf` file (or a folder when it has no `.kf`), `ANAM` the animation group (4 special idle, 5 whole body, 6 upper body, bit 0x80 no return file), `DATA` the parent and previous-sibling form IDs (the siblings are ordered by those links, not by file order), and `CTDA`/`CTDT` the conditions. `PickIdle` (a reference's `Ref.PickIdle`, or the bare command for the speaker of a reply or the script's own actor) walks the tree from the roots in sibling order, skips a node whose conditions do not hold together with everything below it, and takes the first animation node whose conditions hold; a folder that offers nothing hands over to its next sibling. The choice is deterministic (the original's choice among equal candidates is not established, so nothing is randomized). The condition functions answered for an idle are the ones the quests already answer (`GetStage`, `GetStageDone`, `GetQuestVariable` such as `characterGen.uniqueIdle`), plus `GetIsID`, `GetIsRace`, `GetIsSex` for the actor, `GetQuestRunning`, `GetIsCurrentPackage` (from the package the scene runs for the actor) and `MenuMode` (always 0); every other function (combat, weapons, furniture, `GetRandomPercent`, `GetIdleDoneOnce`, `GetInCell` ...) counts as false, so such an idle is never chosen and nothing fails. The result is the action `pickidle` (target reference; `.kf` path, IDLE editor ID, form ID, group flags; empty path when nothing matches). In a stage result the command is answered at the moment it runs, so `set characterGen.uniqueIdle to 27 / GlenroyRef.pickIdle / set characterGen.uniqueIdle to 0` plays the idle for 27 and the later reset does not cancel it. The scene (`play_npc_idle` in `scripts/main.gd`, called by `scripts/quest_stage_bridge.gd`) loads the clip lazily through the NIF asset queue on the NPC's own skeleton, blends from its current pose, plays it (looping when its cycle type is loop, otherwise once) and returns to Idle at the end; an empty pick returns the actor to its default idle; a route that starts, or walking, cancels it; an idle picked for an NPC that is not streamed in yet waits for it. The whole body plays the clip whatever the group (upper-body-only idles are not layered). Not covered: the periodic idle choice of standing NPCs (it needs `GetRandomPercent`, combat and furniture state, and an idle playing between packages, so it is skipped), idle chains (`previous sibling` continuations and "related idles"), no-return-file handling, and re-picking when `evp` changes an actor's package inside the same result as its `PickIdle` (the package for `GetIsCurrentPackage` is the one before the refresh, so Baurus's mourning idle in stage 85 is not chosen yet). The stage-result `Ref.Say topic` is now spoken too (as a `SayTo` to the player), since the intro's replies carry the `PickIdle` calls. `OPENOB_DEBUG_STAGES="CharacterGen:58,CharacterGen:64"` enters those stages one after the other in the running scene to watch the idles in the log (`OpenOB quest:   picks idle: ...`, `OpenOB npc idle: ...`). The inspector shows the tree with `oblivion-inspect <Data> --idles <text|*>` and the picks of a stage with `--tick-world 1 0.1 <Oblivion.exe> CharacterGen:58`.

Unsupported formats and features include plugin load order, animation blending and non-linear KF interpolation, non-diffuse material properties, advanced alpha modes, container contents, and collision decoding from NIF/Havok data. The controller movement values, NPC route behavior, static render-mesh colliders, and game-unit-to-meter scale remain provisional and are not claimed to match the original game's physics.

## Local integration run

On 2026-10-21, the project was launched with the installed base-game `Data` directory. It indexed 1,167,016 ESM records, 35,494 cells, and 17 BSA archives, found `ImperialDungeon01` with 467 references, and instantiated 1,203 meshes from 417 placed NIF references, including world models for pickup items. The run generated 353 static render-mesh colliders and assembled 9 placed NPCs (those figures predate the package-driven routes and are not updated). FaceGen decoding reports 1,736 vertices, 50 symmetric and 30 asymmetric modes, 36 expression morphs, and 6 static morphs. Four dust/light-beam effect NIFs were skipped because nifly reported an out-of-range block index. The ESM `CGPlayerStartMarker` (`0x00032AB5`) is now the primary spawn, with the first valid NPC used only as fallback; this corrects the earlier build that placed the player at `CGAssassin04Ref` (`0x000178C4`). Runtime confirms the marker at Godot position `(5.6787, -1.0160, 0.5392)` and the generated floor 3.5 cm below it; the player is initially snapped to 2 cm above that surface. Valen Dreth is the nearest NPC at 8.18 m. The cell also indexes 9 world pickup candidates. The default male avatar loads `LowerShirt05` and `LowerPants05`; this outfit is not verified against the original player's starting inventory. The equipment-aware NPC loader attached Baurus's six Blades armor pieces and sword, and Uriel's robe, shoes, Amulet of Kings, and sword. `0x0007303C` is `CGValenDrethTauntMarker2`, used only by Valen's route. A temporary support is created only when no generated walkable surface is found below the player. Mouse yaw turns the player; the camera uses a swept sphere against static cell geometry. Several large surfaces still render as flat gray geometry. Original-game placement, Havok collision, and movement behavior remain unverified. The inventory HUD now includes the two default clothing items; pickup and duplicate stacking still need an interactive play check.

The inspector also accepts `--list-assets <prefix>`, `--list-editor-ids <prefix>`, `--find-editor-id <EDID>`, `--gmst-prefix <prefix>`, `--nif-summary <paths...>`, `--rig-summary <paths...>`, and `--kf-summary <paths...>` for local asset inspection. Its cell listing includes placed-reference record types, reference EDIDs, and base-object EDIDs. For example:

```sh
./build/oblivion-inspect "/path/to/Oblivion/Data" --kf-summary "Characters/_male/idle.kf" "Characters/_male/walkforward.kf"
```

## Weapon drawn and combat animations

- `F` draws or sheathes the weapon (`X` cycles the weapons in the inventory, then bare hands). In third person the original weapon-specific KF clips now drive the ready stance, draw/sheath, block, attacks, and weapon-specific movement; the weapon follows the clip's `Attach` key between the hand (`Weapon` bone; a bow in the left hand, `Torch`) and its sheath (`SideWeapon` for one-handed weapons, `BackWeapon` for the rest). Weapon type, speed, reach and damage come from the `WEAP` `DATA` record (`OblivionData.find_weapon`).
- In first person the arms are shown only while the weapon is drawn, as in the original: `scripts/first_person_arms.gd` poses the original `Characters/_1stperson/skeleton.nif`, skinned with the `Arms` and `Hand` meshes (plus worn sleeves and gauntlets, reduced to their arm triangles), with the `Characters/_1stperson` KF clips, and keeps it on the camera. The equip, unequip, idle, walk/run, sneak, jump, block, hit reaction, attack and cast clips are chosen by weapon type (one-hand, two-hand, staff, bow, or fists). The camera node stays at the rig root as the clips give it an absolute eye position. The view model is drawn at 0.4 scale, moved toward the camera by the same factor, so it looks the same and stays out of walls, and 2 cm closer to the viewer so the shoulders stay below the screen edge. The walk and run clips hold the arms nearly still (their bob is in the `Camera01` node, which the view follows by `Oblivion.esm`'s `fFirstPersonCameraMult` = 0.5, and their root translation is dropped), so a step bob and a short trail behind mouse turns are added in code; the strengths are chosen by eye, as `Oblivion.exe` only names `fFirstPersonHandFollowMult` and its values are not read.
- While drawn, `Mouse1` attacks and `Mouse2` blocks instead of grabbing and throwing objects. A swing's `Hit` key checks in front of the player, plays Oblivion's original weapon impact sound, pushes a loose physics object, and staggers a hit actor; a bow's `Release` key plays the original shot sound and looses an arrow (`scripts/combat_projectile.gd`; ammunition is not consumed), whose impact also uses the original sound. Hand and weapon swings use the game's `wpn_swish*` sounds. `C` casts the selected spell (with the weapon sheathed, only the casting arm shows and goes away when the clip ends): the cast clip plays and a target-range spell sends a glowing bolt (colored by fire, frost or shock) that bursts on impact and staggers an actor. Health damage to NPCs is not implemented yet.
- KF text keys (`Hit`, `Release`, `Attach`) are now exposed by the native reader on each animation as `text_keys`.

## Hostile actors

- `scripts/npc_combat.gd` makes actors fight the player. An actor attacks when a script runs `StartCombat` on it, when the player's weapon or spell has hit it, or when it is aggressive enough to attack on sight: the `AIDT` aggression (read natively with the confidence and the `SNAM` factions; `SetAV Aggression` from quest scripts overrides it) is 50 or more and the actor sees the player within 22 m (32 m from aggression 80), as the player has no friends yet. `StopCombat` stands it down.
- A fighting actor draws its weapon, runs at the player along the navigation path and swings with the original `Characters/_male` combat clips (`onehand`, `twohand`, `staff`, `handtohand` attack right/left/power); the hit lands at the clip's `Hit` key if the player is within the weapon's reach, takes off the health Oblivion.exe's melee formula gives (`FUN_00547070`: weapon damage x `fDamageWeaponMult` x the skill, strength and fatigue terms; a power attack times `fDamagePowerAttackBonus`; a block from the front cuts it to 30%, a figure not taken from the executable). An archer stops 4 to 14 m away and shoots arrows that cost the bow's damage on hit. Actors without a weapon use their fists (`FUN_00547280`: `fHandHealthMin` to `fHandHealthMax` by strength, hand-to-hand skill and fatigue, so 1 to 2 health for an untrained assassin). Hits play the original stagger or block-hit reaction and push the target back. Only swinging a weapon (`fFatigueAttackWeaponBase` + damage x `fFatigueAttackWeaponMult`; a power attack times `fPowerAttackFatiguePenalty`) and bare-handed blows consume fatigue; a weapon or claw hit takes health only. The player's worn armor rating (`player_armor_rating`) cuts the damage of a blow by that percent, and a creature has only the health its record gives. At zero fatigue, the actor falls into the original downed idle and uses a weapon-appropriate get-up clip after recovering.
- Actors the plan places disabled (record flag `0x800`) stay hidden until a script runs `Enable` on them, unless the reference has an enable parent (`XESP`): it then follows the parent's state, so `CGAssassin02`-`04` appear with `CGAssassin01`.
- `StartCombat` with a target (`CGAssassin04Ref.startcombat BaurusRef`) makes the actor fight that actor. Actors have health (the record's base health; for an NPC with auto-calculated stats, Oblivion.exe's `FUN_00547f80`: half of strength plus endurance and `iNPCBasePerLevelHealthMult` per level, scaled up from `fLowLevelNPCBaseHealthMult` over the first levels, without the class terms) and a blow from another actor takes it off; the victim flinches, fights back when its aggression is 5 or more, and actors sharing one of its factions (and not the attacker's) come to help within 25 m. At zero health the actor falls and stays down (essential actors keep 1), and the `OnHit` and `OnDeath` blocks of its own script run, as does `Kill` from a script.
- A Find package that targets an actor ends with the finder's greeting: the `HELLO` topic's response for the pair, then the topics it links to, each answered by the other actor (the conditions name who speaks to whom; a CTDA type with bit `0x02` is about the listener), with voice, subtitles and the lines' own results (Baurus reaching the Emperor in the ambush ends with stage 27). An actor event with nothing to run (no quest, NPC record, script or block) and a command whose target is missing are written to the log, once per actor and event.
- A package whose place lies in another cell (the Blades' CGGlenroyToMarkerD in the next dungeon cell) sends the actor to the door of the current cell that leads toward it (a search over the doors' linked cells); at the door the actor leaves, its package counts as done (OnPackageDone runs), and it is placed at the package's marker in that cell, where it stands when the player loads the cell. The walk inside the unloaded cell is not simulated, and an actor away from the cell it was placed in is not shown there.
- Not done yet: the player does not damage actors' health, there is no fleeing, faction reactions set by scripts (`SetFactionReaction`) are not used to pick enemies, and actors in other cells are not reached by `StartCombat`.
